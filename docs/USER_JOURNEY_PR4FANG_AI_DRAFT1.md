# แผนผังการเดินทางของผู้ใช้งานทั้งระบบ (End-to-End User Journey Map)
## โครงการพัฒนาระบบ AI Assistant และคลังองค์ความรู้ดิจิทัล (PR4Fang AI)
**วิทยาลัยการอาชีพฝาง (Fang Industrial and Community Education College)**
*เอกสารฉบับปรับปรุง — วันที่จัดทำ: 4 พฤศจิกายน 2569*

---

## 1. บทนำและบริบทภาพรวมของระบบ (System Context)

ระบบ **PR4Fang AI** ถูกออกแบบมาเพื่อยกระดับการให้บริการข้อมูล การประชาสัมพันธ์ และการจัดการองค์ความรู้ภายในวิทยาลัยการอาชีพฝางอย่างครบวงจร โดยผสานการทำงานระหว่าง:
1. **Physical Frontstage:** หุ่นยนต์ต้อนรับอัจฉริยะ (Robot Reception Kiosk) ติดตั้ง ณ โถงอาคารอำนวยการ รองรับหน้าจอสัมผัส กล้องตรวจจับใบหน้า และการสื่อสารด้วยเสียงภาษาไทยกลางและภาษาไทยถิ่นเหนือ (คำเมือง) ผ่าน Edge TTS
2. **Digital Mobile Frontstage:** LINE Official Account (`@fang_ai`) รองรับการให้บริการ 24 ชั่วโมง ผ่าน Dynamic Rich Menu, Flex Message Cards และระบบตอบกลับอัตโนมัติด้วย AI
3. **Internal Backstage & CMS:** Web Management Portal สำหรับบุคลากร (Staff) ใน 4 ฝ่าย 23 งาน และผู้ดูแลระบบ (Admin)
4. **AI & Automation Engine:** สถาปัตยกรรม Retrieval-Augmented Generation (RAG) เชื่อมต่อ Google Gemini 1.5 Flash และระบบดักจับคำถามที่ไม่มีคำตอบ (`knowledge_gap_logs`) เพื่อการเรียนรู้อย่างต่อเนื่อง

## 2. เมทริกซ์กลุ่มผู้ใช้งานและช่องทาง (Actors & Touchpoints Matrix)

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                         PR4FANG AI OMNICHANNEL ECOSYSTEM                         │
└────────────────────────────────────────┬─────────────────────────────────────────┘
                                         │
        ┌────────────────────────────────┼────────────────────────────────┐
        ▼                                ▼                                ▼
┌─────────────────┐            ┌───────────────────┐            ┌──────────────────┐
│  Robot Kiosk    │            │  LINE OA Service  │            │  Web Management  │
│  (Physical Hub) │            │  (Mobile Hub)     │            │  (Portal & CMS)  │
```

### กลุ่มผู้ใช้งานหลัก (Personas):
1. **Persona 1: ผู้มาติดต่อภายนอกและผู้ปกครอง (Visitors & Parents)**
   * *เป้าหมาย:* เดินทางมาติดต่อราชการ สมัครเรียนให้บุตรหลาน ชำระค่าธรรมเนียม สอบถามสถานที่ห้อง/ตึก
   * *ช่องทางหลัก:* หุ่นยนต์ต้อนรับหน้าโถงอาคาร (On-site) และ LINE OA สำหรับศึกษาข้อมูลก่อนเดินทาง
2. **Persona 2: นักเรียนและนักศึกษาปัจจุบัน/ผู้สนใจเข้าศึกษา (Students)**
   * *เป้าหมาย:* หาข้อมูลแผนการเรียน ปวช./ปวส., ตารางสอบ, ทุนการศึกษา, ปฏิทินกิจกรรม, กฎระเบียบ
   * *ช่องทางหลัก:* LINE OA (24/7 ผ่านสมาร์ทโฟน) และหุ่นยนต์ Kiosk ในช่วงพักระหว่างวัน
3. **Persona 3: ครูและเจ้าหน้าที่ประจำฝ่ายงาน (Staff / Department Officers)**
   * *เป้าหมาย:* เพิ่ม/ปรับปรุงข้อมูลระเบียบและข่าวสารของฝ่ายตนเอง (4 ฝ่าย 23 งาน), ส่งประกาศด่วน, ผูกบัญชีเพื่อรับงาน
   * *ช่องทางหลัก:* Web Management Portal (`/knowledge`), LINE OA (ผูกบัญชีด้วย OTP 6 หลัก)
4. **Persona 4: ผู้บริหารและผู้ดูแลระบบ (Administrators & Executives)**
   * *เป้าหมาย:* ติดตามภาพรวม KPI ประสิทธิภาพ AI, ตรวจสอบ Knowledge Gaps, บริหารจัดการสิทธิ์และความปลอดภัย
   * *ช่องทางหลัก:* Admin Dashboard (`/dashboard`, `/analytics`, `/settings`)

## 3. แผนภาพเส้นทางทั้งระบบ 6 ลำดับขั้นตอน (The 6-Stage End-to-End System Journey)

วงจรการทำงานของระบบแบ่งออกเป็น 6 ขั้นตอนหลัก ตั้งแต่ต้นน้ำ (การเตรียมข้อมูล) จนถึงปลายน้ำ (การปิดวงจรปรับปรุงระบบ):

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   STAGE 0   │ ──> │   STAGE 1   │ ──> │   STAGE 2   │
│ Ingestion & │     │ Discovery & │     │ Interaction │
│ Governance  │     │ Approach    │     │  & Inquiry  │
└─────────────┘     └─────────────┘     └─────────────┘
                                               │
                                               ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   STAGE 5   │ <── │   STAGE 4   │ <── │   STAGE 3   │
│ Loop Closure│     │ Hand-off &  │     │ AI Reasoning│
│ & Analytics │     │ Action      │     │  & Response │
└─────────────┘     └─────────────┘     └─────────────┘
```

### STAGE 0: การเตรียมคลังความรู้และตั้งค่าระบบ (Knowledge Ingestion & Governance)
*วงจรต้นน้ำโดยเจ้าหน้าที่และผู้ดูแลระบบ ก่อนเปิดให้บริการแก่สาธารณะ*

* **ขั้นตอนการปฏิบัติงาน (Actions):**
  1. ครู/เจ้าหน้าที่แต่ละฝ่าย (เช่น งานแนะแนว ฝ่ายวิชาการ) กรอกข้อมูลระเบียบการรับสมัคร แผนการเรียน และ FAQ ผ่านหน้า Web Management Portal (`/knowledge/new`)
  2. ระบบตรวจสอบความถูกต้อง (Schema Validation) และจัดเก็บข้อมูลความรู้ 83 รายการเข้าสู่ฐานข้อมูล SQLite (`pr4fang.db`) และซิงค์ไปยัง Supabase Cloud DB
  3. AI Engine ทำการสร้าง Text Normalization, แยกคำ, และจัดดัชนีสำหรับ Semantic Search พร้อมจัดกลุ่มขอบเขตสิทธิ์ตามฝ่ายงาน (Department Scope)
* **Touchpoints & Data Tables:** Web CMS Form, `knowledge_items`, `knowledge_attachments`
* **สถานะความพร้อม:** ผ่านการทดสอบ Phase 3 และความปลอดภัยสมบูรณ์ 100%

### STAGE 1: การเข้าถึงและเริ่มเปิดบทสนทนา (Discovery & Approach)
*จุดเริ่มต้นของประสบการณ์ผู้ใช้ ทั้งที่เดินทางมาวิทยาลัยและเข้าใช้งานทางไกล*

| มิติการวิเคราะห์ | ช่องทางหุ่นยนต์ (Physical Robot) | ช่องทาง LINE OA (Mobile Chat) |
|---|---|---|
| **บริบทและสถานที่** | โถงชั้น 1 อาคารอำนวยการ วิทยาลัยการอาชีพฝาง | ที่บ้าน/โรงเรียนเดิม ผ่านสมาร์ทโฟนส่วนตัว |
| **การกระทำของผู้ใช้** | เดินเข้ามาในรัศมี 1.5 - 2 เมตรของตัวหุ่นยนต์ | สแกน QR Code จากป้ายไวนิล/เพจ หรือค้นหาไอดี LINE |
| **สิ่งที่ระบบทำ (Frontstage)** | กล้องตรวจจับใบหน้า ➔ จอภาพเปลี่ยนเป็นแอนิเมชันต้อนรับ ➔ ลำโพงเล่นเสียงทักทาย: *"สวัสดีเจ้า ยินดีต้อนฮับสู่วิทยาลัยการอาชีพฝาง..."* พร้อมแสดง 6 ปุ่มคำถามด่วน | ส่งการ์ด Greeting Message อัตโนมัติ แนะนำตัวน้องฝางคำ AI พร้อมเปิดแถบ 6 เมนูหลัก (Rich Menu) |
| **เบื้องหลังระบบ (Backstage)** | ทริกเกอร์ `welcome-audio` โหลดไฟล์เสียง Edge TTS Sec-MS-GEC v2 (แคชในหน่วยความจำ) | Webhook รับ Follow Event ➔ บันทึกประวัติลง `line_followers` |
| **ความรู้สึกของผู้ใช้** | แปลกใจ ตื่นเต้น รู้สึกได้รับการต้อนรับอย่างอบอุ่นและเป็นกันเอง | สะดวก เข้าถึงง่าย ไม่ต้องโหลดแอปใหม่ |

### STAGE 2: การซักถามและมีปฏิสัมพันธ์ (Interaction & Multi-modal Inquiry)
*ผู้ใช้ส่งคำถามหรือสิ่งที่ต้องการทราบเข้าสู่ระบบ*

* **รูปแบบการป้อนคำถาม (Input Modalities):**
  1. **โหมดสัมผัส (Touch/Direct Tap):**
     * หุ่นยนต์: แตะปุ่ม Quick Suggestions (เช่น "สาขาวิชาที่เปิดสอน", "การสมัครเรียน", "ค่าธรรมเนียม/ค่าเทอม")
     * LINE OA: แตะปุ่มบน Rich Menu 6 ช่อง (หลักสูตร, รับสมัคร, ปฏิทิน, FAQ, ติดต่อ, ผูกบัญชี)
  2. **โหมดเสียงภาษาถิ่น (Voice Input / Dialect Speech):**
     * ผู้ปกครองกดไมโครโฟนหน้าหุ่นยนต์แล้วพูด: *"ค่าเทอม ปวช. จ่ายตี้ไหนและเต้าใดเจ้า"*
     * ระบบ Web Speech API / Mic Array รับสัญญาณเสียง ➔ แปลงเป็นข้อความ (STT) ➔ ตรวจจับลักษณะไวยากรณ์คำเมือง (`เจ้า`, `ตี้ไหน`, `เต้าใด`)
  3. **โหมดพิมพ์ข้อความธรรมชาติ (Free-text Chat):**
     * นักเรียนพิมพ์ใน LINE: *"จบ ม.3 อยากเรียนช่างยนต์ ต้องเตรียมเอกสารอะไรบ้างครับ มีรอบโควตาไหม"*
* **ระบบจัดการความคาดหวัง:**
  * หน้าจอแสดง Waveform แสดงสถานะว่าหุ่นยนต์กำลังฟัง
  * ขึ้นสถานะกำลังประมวลผล (Processing Indicator) ภายใน 0.5 วินาที เพื่อลดความอึดอัดของผู้ใช้

---

### STAGE 3: การประมวลผลและการตัดสินใจของ AI (Reasoning & Confidence Scoring)
*กลไกหลังบ้าน RAG Pipeline ทำงานเบื้องหลังอย่างรวดเร็ว (เป้าหมายเวลา < 1.5 วินาที)*

```
[ ข้อความคำถาม ] ──> [ Text Normalizer & Dialect Detector ]
                                  │
                                  ▼
                     [ Semantic Vector Search ]
                      (ค้นหาใน 83 Knowledge Items)
                                  │
                                  ▼
                     [ Decision: Confidence Score ]
                                  │
         ┌────────────────────────┼────────────────────────┐
         ▼                        ▼                        ▼
  คะแนน ≥ 0.85 (High)     คะแนน 0.70-0.84 (Med)      คะแนน < 0.70 (Low)
   [ Happy Path ]           [ Clarify Path ]          [ Fallback Path ]
ตอบตรงเป้า+อ้างอิงชัดเจน    ตอบพร้อมขอความชัดเจน      ตอบสุภาพ+ส่งต่อห้องทำงาน
                                                    + บันทึก Knowledge Gap!
```

1. **กรณี Happy Path (ความมั่นใจสูง ≥ 0.85):**
   * AI ค้นพบเอกสารที่เกี่ยวข้องจากฝ่ายวิชาการ (งานทะเบียน/งานแนะแนว)
   * Gemini 1.5 Flash ร่างคำตอบที่กระชับ ไม่เยิ่นเย้อ อ้างอิงระเบียบปีการศึกษาปัจจุบัน
   * บันทึกคำถามและคะแนนความเชื่อมั่นลงใน `ai_query_logs` และบันทึกแหล่งอ้างอิงลง `ai_retrieved_sources`
2. **กรณี Fallback Path (ความมั่นใจต่ำ < 0.70 หรือคำถามนอกขอบเขต):**
   * ตัวอย่าง: *"ขอยืมเงินวิทยาลัยได้ไหม"*, *"ครูสมชายอยู่บ้านไหม"*
   * ระบบตัดเข้าโหมดปลอดภัย (Safe Fallback) โดยอัตโนมัติ:
     *"ขออภัยเจ้า น้องฝางคำยังไม่มีข้อมูลส่วนนี้ในระบบ ขอแนะนำติดต่อสอบถามได้ที่ห้องประชาสัมพันธ์ หรือโทร 053-451-xxx ต่อ 101 เจ้า"*
   * **จุดสำคัญ:** ระบบจะนำคำถามนี้บันทึกลงตาราง `knowledge_gap_logs` อัตโนมัติ พร้อมตั้งสถานะเป็น `OPEN` เพื่อส่งต่อให้คนจริงมาเติมคำตอบ

### STAGE 4: การส่งมอบคำตอบและการส่งต่อ (Delivery, Routing & Hand-off)
*การแปลงข้อมูลความรู้ให้กลายเป็นการปฏิบัติจริงของผู้ใช้*

| องค์ประกอบ | หุ่นยนต์ Kiosk หน้างานจริง | LINE Official Account |
|---|---|---|
| **รูปแบบคำตอบ (Visual)** | แสดงการ์ดสรุปข้อความขนาดใหญ่ อ่านง่าย จัดลำดับด้วย Bullet Points | ส่งกลับเป็น **LINE Flex Message** โทนสีเขียว-ทองมาตรฐานวิทยาลัย พร้อมปุ่มกด Action |
| **รูปแบบเสียง (Audio)** | สังเคราะห์เสียงพูดอัตโนมัติผ่าน Edge TTS ภาษาไทยสำเนียงสุภาพ และปรับให้เข้ากับภาษาคำเมือง | ไม่มีเสียง (เน้นข้อความและไฟล์แนบ) |
| **การนำทาง (Wayfinding)** | หน้าจอแสดง **แผนผังอาคาร (Indoor Campus Map)** ไฮไลต์ลูกศรนำทางไปยังตึกเป้าหมาย (เช่น ตึก 2 ชั้น 1 งานทะเบียน) | ส่งพิกัด Google Maps ของวิทยาลัย และตำแหน่งห้องติดต่อ |
| **การส่งต่อมนุษย์ (Human Hand-off)** | แสดงเบอร์โทรศัพท์ภายในห้องงาน และปุ่มกด *"ขอพบบุคลากรประจำจุดประชาสัมพันธ์"* | มีปุ่มกด *"โทรติดต่อเจ้าหน้าที่"* หรือลิงก์เปิดแชทกับเจ้าหน้าที่ |

### STAGE 5: การเชื่อมต่อข้ามช่องทาง (Cross-Channel Synergy)
*สะพานเชื่อมระหว่างโลกออฟไลน์กับโลกออนไลน์อย่างไร้รอยต่อ*

1. **จากหุ่นยนต์สู่มือถือ (Robot to Mobile Handoff):**
   * ขณะที่ผู้ปกครอง/นักเรียนอ่านข้อมูลหน้าหุ่นยนต์ ระบบจะสร้าง **Dynamic QR Code** บนมุมขวาของหน้าจอ
   * ข้อความเชิญชวน: *"สแกนเพื่อเก็บข้อมูลสมัครเรียนและแผนที่นี้ไว้ในมือถือของคุณ"*
   * เมื่อผู้ใช้ยกสมาร์ทโฟนขึ้นมาสแกน QR Code:
     1. ระบบจะเปิดเข้าสู่ห้องแชท LINE OA ของวิทยาลัยการอาชีพฝางทันที
     2. ระบบหลังบ้านส่งสรุปเอกสารที่เพิ่งคุยค้างไว้หน้าหุ่นยนต์ลงใน LINE ให้อัตโนมัติ ผู้ปกครองสามารถนำเอกสารนี้ติดตัวไปยื่นที่ห้องทะเบียนได้ทันที
2. **การผูกบัญชีบุคลากร (Staff Account Linking via LINE):**
   * สำหรับครูและเจ้าหน้าที่ เมื่อกดเมนู "ผูกบัญชีบุคลากร" ใน LINE OA
   * ระบบจะสร้างรหัส OTP 6 หลัก (อายุ 10 นาที) ผ่าน `line_account_link_requests`
   * ครูนำรหัสมากรอกในระบบ Web Portal เพื่อเชื่อมโยงบัญชี ทำให้ได้รับสิทธิ์รับแจ้งเตือนงานด่วนและส่ง Broadcast ประจำแผนกได้ทันที

### STAGE 6: การปิดวงจรปรับปรุงระบบ (Continuous Loop & Knowledge Evolution)
*การทำให้ระบบ "ยิ่งใช้งาน ยิ่งฉลาดขึ้น" โดยอาศัยผู้ดูแลระบบและเจ้าหน้าที่*

```
[ ผู้ใช้ถามคำถามที่ระบบไม่รู้ ] ──> [ Auto-log เข้า knowledge_gap_logs ]
                                                  │
                                                  ▼
[ ประมวลผลใน Admin Analytics ] <── [ แจ้งเตือนไปยัง Admin Dashboard ]
               │
               ▼
[ มอบหมายฝ่ายงานที่เกี่ยวข้อง ] (เช่น งานทะเบียน / ฝ่ายวิชาการ)
               │
               ▼
[ ครูอัปเดตคำตอบผ่าน Web Portal ] ──> [ อัปเดตฐานข้อมูล ] ──> [ หุ่นยนต์ & LINE ฉลาดขึ้นทันที ]
```

1. **Daily Audit:** ผู้ดูแลระบบเปิดหน้า Analytics (`/analytics/ai-performance` และ `/analytics/knowledge`)
2. **Review Knowledge Gaps:** ตรวจสอบรายการในตาราง `knowledge_gap_logs` ว่ามีคำถามใดที่ผู้ปกครองถามบ่อยแต่ AI ตอบไม่ได้
3. **Collaborative Updating:** มอบหมายให้เจ้าหน้าที่ฝ่ายงานพิมพ์ข้อมูลคำตอบที่ถูกต้องลงใน Web Management Portal (`/knowledge`)
4. **Auto Deployment:** เมื่อบันทึกข้อมูลแล้ว คำตอบใหม่จะถูกอัปเดตไปยังทั้งหุ่นยนต์และ LINE OA ภายในระบบทันที

## 4. ตารางเปรียบเทียบ Service Blueprint (Frontstage vs Backstage)

| ลำดับขั้นตอน | ผู้ใช้ทำอะไร (Customer Action) | หน้าบ้านเห็นอะไร (Frontstage Touchpoint) | หลังบ้านประมวลผลอะไร (Backstage Engine) | ฐานข้อมูลที่รองรับ (Database Tables) |
|:---:|---|---|---|---|
| **1** | เดินเข้าใกล้หุ่นยนต์ | แอนิเมชันน้องฝางคำ + เสียงทักทายต้อนรับ | Face Detection ➔ Welcome Audio Sec-MS-GEC v2 | `system_settings`, `drive_media_cache` |
| **2** | ถามคำถามด้วยเสียง/พิมพ์ | ข้อความถอดเสียง + ไอคอนกำลังประมวลผล | Web Speech STT ➔ Dialect Classifier | `ai_engine_configs` |
| **3** | รอคำตอบ (< 1.5 วินาที) | แอนิเมชันคิด ➔ แสดงการ์ดคำตอบสรุป | RAG Vector Search ➔ Gemini 1.5 Flash Scoring | `knowledge_items`, `departments` |
| **4** | รับคำตอบ & ฟังเสียง | เสียงพากย์ Edge TTS + ปุ่มดาวน์โหลดเอกสาร | SSML Speech Generation ➔ Audio Streaming | `ai_query_logs`, `ai_retrieved_sources` |
| **5** | สแกน QR Code ไปดูต่อ | เปิดแอป LINE ได้รับสรุปข้อมูลเข้าแชท | LINE Webhook ➔ Flex Message Dispatcher | `line_followers`, `line_rich_menus` |
| **6** | ถามคำถามที่ไม่มีข้อมูล | ข้อความแจ้งเบอร์โทรศัพท์และห้องติดต่อ | Fallback Handler ➔ บันทึก Gap Alert | `knowledge_gap_logs` |
| **7** | เจ้าหน้าที่เติมคำตอบ | อัปเดตผ่าน Web Management Portal | Direct Database Update & Cache Refresh | `knowledge_items`, `knowledge_version_history` |

## 5. แผนรับมือกรณีเกิดข้อผิดพลาด (Edge Cases & Fallback Workflows)

1. **กรณีเสียงดังรบกวนในโถงอาคาร (High Ambient Noise):**
   * *อาการ:* ระบบถอดเสียง STT ไม่ชัดเจนหรือมีความเงียบเกิน 5 วินาที
   * *การแก้ไขตาม Journey:* ระบบจะเล่นเสียงนุ่มนวล *"ขอสุมาเจ้า น้องฝางคำบ่ค่อยได้ยิน ท่านสามารถแตะเลือกหัวข้อบนหน้าจอนี้ได้เลยเจ้า"* พร้อมขยายปุ่ม Quick Suggestions ให้เด่นชัดขึ้น
2. **กรณีสัญญาณอินเทอร์เน็ตหลุดชั่วคราว (Offline Degraded Mode):**
   * *อาการ:* ไม่สามารถเรียก API Gemini Cloud ได้
   * *การแก้ไขตาม Journey:* หุ่นยนต์จะดึงข้อมูลที่ถูกแคชไว้ในเครื่อง (Local SQLite Cache) เฉพาะหัวข้อสำคัญ เช่น แผนที่อาคาร, เบอร์โทรติดต่อฉุกเฉิน และระเบียบการหลัก มาแสดงเป็นภาพนิ่งแทน
3. **กรณีผู้ใช้ถามภาษาคำเมืองระดับลึก (Deep Local Dialect):**
   * *อาการ:* ศัพท์โบราณหรือสำเนียงเฉพาะถิ่นที่ไม่ตรงกับ Lexicon กลาง
   * *การแก้ไขตาม Journey:* AI จะทำการจับเฉพาะคีย์เวิร์ดสำคัญ (เช่น *ค่าเทอม*, *ช่าง*, *สมัคร*) หากยังไม่มั่นใจจะสรุปทวนถามซ้ำ: *"ต้องการสอบถามเรื่องการสมัครเรียนช่างอุตสาหกรรมใช่ก่อเจ้า"*
